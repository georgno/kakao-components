Description list

<kakao-description-list> - key/value rows for summary and detail screens, drawn as a real <dl>: the term muted, the value in the text colour. Term beside value where there is room, term above value where there is not.

Rows · list-data, <dt> / <dd>

list-data takes a JSON array of [term, value] pairs or {"term", "value"} objects, set as plain text. Values with markup (a badge, a link) are written as native <dt> and <dd> children. Both together: the rows from list-data come first.

Several values, shared values

Empty values · empty-text

A value that is null, an empty text or an empty <dd> shows a placeholder in the muted colour, a dash by default. A screen reader hears empty-label ("Not set") in place of the dash; a placeholder that is a word is read as it is.

Layout · layout="stacked"

Side by side is the default: the terms in a column of their own (--kakao-description-list-term-width). layout="stacked" puts each term above its value at every width. A side-by-side list stacks by itself when a row gets narrower than --kakao-description-list-stack-below, as on a phone, the way a data table wraps into label/value blocks there.

Dividers and size · dividers, size="sm"

dividers draws a hairline between the rows. size="sm" is the dense form: smaller type, less space between the rows.

Columns · columns

With columns (2, 3 or 4) the pairs fill a grid, row by row. A column falls away while it would be narrower than --kakao-description-list-column-min-width, so on a phone it is one column again. Stacked pairs suit a grid best.

Three columns, stacked

Values at the end · align="end"

For amounts in a summary: the values line up at the end of the row. A stacked list keeps them at the start.
