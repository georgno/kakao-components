Table

<kakao-table> - a data table with sortable headings, row selection and a sticky header. It draws a real <table> from list-data, or enhances the server-rendered table it is wrapped around. On a phone each row wraps into a block of label / value pairs, so no column is squeezed or hidden. Light DOM: load table.css with table.js.

Columns and rows

list-data is { "columns": […], "rows": […] }. A column has a key and a label, and may have a type, align, width and sortable. A number column is set in tabular figures at the end of its cell. An empty value shows “—”, which a screen reader hears as “Not set”.

From list-data

Sorting

A sortable column’s heading is a button with a sort icon; its <th> carries aria-sort. A click sorts ascending, the next descending, the third puts the rows back as written. sort names the sorted column the Yii2 way: "name" ascending, "-name" descending. Numbers sort as numbers, texts by the reader’s language, empty cells last. Every change fires a cancelable sort-change.

Selection

selectable adds a checkbox to each row and “select all” to the heading row, which shows a dash while only some rows are selected. selection-change carries the ids of the selected rows; selected reads and sets them. With selection-name the checkboxes carry that name and the row id, so the selection is submitted with the form around the table.

Sticky header

With sticky-header the heading row stays in view while the page scrolls past a long table. --kakao-table-sticky-top is where it stops, for a page with a fixed bar at the top; --kakao-table-head-bg is its fill, the surface the table sits on.

On a phone

While the table is narrower than --kakao-table-stack-below (36rem; its own width, not the window’s) each row becomes a block of label / value pairs with the column heading as the label. The heading row is hidden, so there is no sticky header; “Sort by” and “Select all” move into a line above the blocks, and a row’s checkbox sits at the top of its block. layout="stacked" asks for this form at every width.

Scrolling instead · scroll

For a table that only makes sense with its columns side by side, like a comparison of numbers. It never wraps: too wide for its frame, it scrolls sideways in it, with the edge fade on each side that has more. The frame takes keyboard focus so it can be scrolled with the arrow keys.

Scrolling in a frame of its own · scroll sticky-header

With --kakao-table-max-height the frame also scrolls down, and the sticky header sticks to the frame.

A table from the server

Without list-data the component takes the <table> inside it and enhances it where it is: the page works before the script has loaded, and links, buttons and page scripts in the cells keep working. Columns are read from the first heading row (data-type, data-align, data-sortable, data-width, data-hide-label), row ids from data-key on the <tr>, as Yii2’s GridView writes it. A cell sorts by its text, or by data-sort-value.

Yii2 sorter links

A heading whose only content is a link is sortable through that link: it gets the icon and aria-sort (from the link’s class asc or desc) and stays a real link, so the server sorts. sort-change fires first with the link’s href; cancel it to load the rows yourself.

Empty and loading

A table without rows shows an empty state under its headings: a kakao-empty-state where that component is loaded, a plain text otherwise, with empty-heading and empty-message. Your own goes in as a child marked data-table-empty. While loading is set the rows give way to placeholder rows (kakao-skeleton where loaded), and the table is aria-busy.

With a pager

The table does not page by itself: put a kakao-pagination below it and set the page’s rows when it fires page-change. Sorting here goes over all the rows, so the table is in sort-mode="server" and the script sorts before it cuts out the page.

From script

columns and rows are the property form of list-data. A column set from script may carry render(value, row, column), which returns the cell’s content as a node or a text: badges, links, a row of buttons. hideLabel keeps a heading for screen readers only and leaves the wrapped cell without a label, for an action column. KakaoTable.types takes your own column types (align, compare, format).

Rendered cells and a type of your own

Other words

KakaoTable.texts sets the words for every table: sortBy, notSorted, ascending and descending (“{label}, ascending”), selectAll, selectRow (“Select {row}”), emptyHeading, emptyLabel and loading.
