How the file upload works

A walk through components/file-upload/file-upload.js: how a file gets from the user's desktop into the list, into the form, and out again.

The shape of the file

The whole component is one file of about 1,000 lines, with no dependencies. It is wrapped in an IIFE that returns early when kakao-file-upload is already defined, so loading the script twice is harmless. Inside, top to bottom:

Helpers
formatBytes, parseSize, extOf, categoryOf, matchesAccept, fileKey: small pure functions with no DOM access.
Template
One <template> holding the shadow root's <style> and markup, cloned for every instance.
Class
KakaoFileUpload extends HTMLElement: lifecycle, public API, the add/remove logic, rendering, and the pointer and drag handlers.

It renders into a shadow root, so page CSS cannot reach inside. Theming still works because custom properties (--kakao-*) inherit through the shadow boundary.

What's inside the shadow root

.root                     size container (for the horizontal fallback)
  .label                  the label attribute's text
  .layout
    .pick
      .drop               the dotted drop area, clickable
        .drop-icon
        .drop-text        "Drop files here, or"
        <slot name="button"> Browse button (fallback <button> inside)
        .drop-hint        built from accept / max-size
      <input type="file" hidden>
      .message            role="alert": why files were not added
    .files
      .summary            "3 files · 2.4 MB" + Clear all
      ul.list             one li.item per file

The real <input type="file"> is hidden and never shown. It is only used to open the operating system's file dialog. The list of files is not the input's files; the component keeps its own array, which is what lets every pick add to the list instead of replacing it.

The state it keeps

Everything the component knows lives in a handful of fields set in the constructor:

this._entries = [];     // [{ id, file, url }]: the list, in order
this._nextId = 1;       // stable id per entry, used to find rows
this._pending = [];     // API calls made before the element was connected
this._dragDepth = 0;    // counts dragenter/dragleave pairs
this._raf = 0;          // pending animation frame for the spotlight
this._pointer = null;   // last pointer position, applied in that frame
this._formDisabled = false; // set by a disabled <fieldset>

Each entry holds the File itself, a numeric id (indexes shift on removal, ids don't) and, for images only, an object URL (blob:…) used as the thumbnail's src.

Lifecycle

Constructor

Attaches the shadow root, clones the template, calls attachInternals() (for form support, see below), caches every element it will touch, and binds the event handlers once so the same function references can be removed later.

connectedCallback

  1. Adds the listeners: click, pointer and drag events on .drop, change on the input, a click on the list (one delegated listener for all remove buttons) and on Clear all.
  2. Syncs the label, the hidden input's accept/multiple and the disabled state, then renders the (empty) list.
  3. Sets up the Browse button (see the browse button).
  4. Runs the queued calls. addFiles(), removeFile() and clear() push themselves onto _pending when called before the element is in the document, so a script can fill the component before it's attached.

disconnectedCallback

Removes every listener and cancels a pending animation frame. Object URLs are deliberately kept, because a disconnect is often just the element moving to another spot in the DOM.

attributeChangedCallback

Ignored until connected. label, hint, accept and max-size resync the label, hint and input; multiple resyncs the input; disabled resyncs the disabled state; name rewrites the form value. max-files needs no sync: it is read fresh each time files are added.

Browse

The click handler sits on the whole .drop area, so clicking anywhere in it (including the Browse button, whose click bubbles up through the slot) opens the dialog. open() checks the disabled state and calls click() on the hidden input. When the user confirms, _onInputChange passes the picked files to _add and then resets the input:

_onInputChange() {
  this._add(Array.from(this._inputEl.files || []), []);
  this._inputEl.value = ''; // so picking the same file again still fires change
}

Drop

_onDrop prefers dataTransfer.items over dataTransfer.files, because only items can tell a folder from a file. For each item it asks webkitGetAsEntry(); a directory goes straight into rejected with reason "folder", a file goes into the list to check. Browsers without items fall back to the plain files list.

items.forEach((item) => {
  if (item.kind !== 'file') return;            // dragged text, links…
  const entry = item.webkitGetAsEntry?.();
  const file = item.getAsFile();
  if (entry && entry.isDirectory) rejected.push({ file: null, name, reason: 'folder' });
  else if (file) files.push(file);
});
this._add(files, rejected);

Script

addFiles(fileList) accepts a FileList or an array, turns it into an array and calls _add with the same rules a pick gets.

The rules in _add()

This is the heart of the component (lines 825–870). In order:

  1. Single mode. When multiple is off, only the first new file is kept, and every current entry is dropped (its object URL revoked, its file noted as removed).
  2. Read the rules once: accept, parseSize(max-size) (a missing or unreadable value means Infinity), max-files, and a Set of keys for the files already in the list.
  3. Check each file, first failure wins: 
    if (!matchesAccept(file, accept))       reason = 'type';
else if (file.size > maxSize)           reason = 'size';
else if (keys.has(fileKey(file)))       reason = 'duplicate';
else if (this._entries.length >= maxFiles) reason = 'max-files';
  4. Keep the ones that pass: give them an id, create an object URL if the file is an image, push the entry and add its key to the set (so the same file twice in one drop is caught too).
  5. Report rejections: one file-reject event per file, and a single line in the role="alert" message, at most three names plus "and N more".
  6. If anything changed: render with the new ids (so only those rows play the entry animation), update the form value, and fire files-change with { files, added, removed }.

How the checks decide

matchesAccept
Splits accept on commas. .pdf matches the end of the file name, image/* the start of the MIME type, anything else the exact MIME type. The file dialog already filters by accept, but drops don't, which is why the component checks again.
parseSize
Reads "5MB", "500 kb" or plain bytes, in powers of 1024.
fileKey
name|size|lastModified. The browser gives no path, so this is the best available "same file" test.
max-files
Counted against the list as it grows during the loop, so a drop of 5 files into a list with 1 free slot keeps the first and rejects the rest.

Removing files

removeFile(index), a row's remove button and clear() all go through _remove(entries):

  1. It remembers the index of the first removed row and whether focus was inside the component, before anything changes, because the focused button is about to disappear.
  2. It adds is-removing to the rows, which plays a 180 ms slide-out (REMOVE_MS) and turns off pointer events so the row can't be clicked twice.
  3. After that delay (or at once with reduced motion), finish() revokes the object URLs, filters the entries, re-renders, updates the form value and fires files-change with the removed files.
  4. If focus was inside, _restoreFocus moves it to the remove button now at the same index, else the last one, else the drop area.

The remove buttons don't each have a listener; one click listener on the <ul> uses closest('.remove') and the button's data-id to find the entry.

Rendering the list

_render(newIds) is a full rebuild: it empties the <ul> and creates one <li> per entry with three parts:

Thumbnail
For images, an <img> on the entry's object URL. Otherwise a page icon with the extension on a small tag. categoryOf sorts files into image, video, audio, pdf, archive, text or file, from the MIME type and, for archives, the extension. The category sets data-cat, and CSS maps it to a colour (--kakao-file-upload-type-*).
Info
The file name (cut with an ellipsis, full name in title) and a meta line: size from formatBytes and the extension.
Remove
A button named "Remove file name".

Then it updates the summary line ("3 files · 2.4 MB", a polite live region), hides it when the list is empty, and hides Clear all for fewer than two files. Text is always set with textContent, never HTML, so file names can't inject markup.

A full rebuild is simple and fine for the dozens of files a form normally gets. Object URLs are created once per entry, not per render, so images don't decode again.

Taking part in a form

The class's static formAssociated getter returns true and keeps an ElementInternals object. That gives three things without a hidden input in the page:

  • Submission. _syncFormValue builds a FormData with every file appended under the name attribute and hands it to setFormValue. A normal form submit (or new FormData(form)) then includes all files. No name or no files means setFormValue(null).
  • Reset. formResetCallback calls clear().
  • Disabled fieldset. formDisabledCallback stores the flag in _formDisabled; _isDisabled() checks it alongside the element's own disabled attribute.

The form value is rewritten after every add, remove and name change.

The drop area: dots, spotlight and drag state

Two layers of dots

The dotted background is pure CSS on two pseudo-elements of .drop. ::before is a repeating radial-gradient of small dots. ::after is the same grid with slightly bigger, tinted dots, cut down by a radial mask-image centred on --_mx / --_my. Where the mask is opaque the tinted dots show, so they appear only around the pointer.

Following the pointer

pointermove doesn't write styles directly. It stores the position and asks for one animation frame; any further moves in that frame just overwrite the stored position. The frame then converts it into coordinates relative to the drop area and sets the two custom properties:

_trackPointer(clientX, clientY) {
  this._pointer = { x: clientX, y: clientY };
  if (this._raf) return;                 // a frame is already booked
  this._raf = requestAnimationFrame(() => {
    this._raf = 0;
    const r = this._dropEl.getBoundingClientRect();
    this._dropEl.style.setProperty('--_mx', `${this._pointer.x - r.left}px`);
    this._dropEl.style.setProperty('--_my', `${this._pointer.y - r.top}px`);
  });
}

That keeps it to at most one style write per frame. The class is-pointer fades the spotlight layer in; pointerleave removes it. With prefers-reduced-motion the handler returns early and no spotlight is drawn.

Drag over

  • dragover must call preventDefault(), or the browser won't fire drop on the element. It also sets dropEffect = 'copy' and feeds the same spotlight, with a bigger radius while dragging.
  • dragenter and dragleave fire again for every child element the drag crosses. Toggling the highlight on each would make it flicker, so _dragDepth counts enters minus leaves and the is-dragover class only goes when it is back to zero. drop resets the counter.

The browse button

The keyboard way in is a "Browse files" button. The shadow root ships a plain fallback <button> inside <slot name="button">. In _ensureButton, the component waits for customElements.whenDefined('kakao-button') and then appends a <kakao-button slot="button"> to its own light DOM. Since it is slotted, it replaces the fallback, and since it lives in the light DOM, the page's button.css styles it like every other button.

It skips all of this when the page has already put its own [slot="button"] element inside. Its own button carries a private _kakaoAuto flag, so _syncLabel only rewrites the aria-label ("Browse files for label") on the button it created, never on one the page provided.

How the styles are set up

Every value in the @kakao-settings block resolves in three steps, for example:

--_accent: var(--kakao-file-upload-accent,   /* 1. per-component override */
             var(--kakao-color-primary,      /* 2. the theme token */
             #4f46e5));                      /* 3. hard fallback */

The rest of the CSS only reads the private --_* names. The block between the @kakao-settings markers is written by construction.html, not by hand. The horizontal layout uses a container query on .root, so it falls back to stacked when the component itself is narrower than 34rem, whatever the viewport.

Events

Review notes

Things noticed while reading the code. None of them is fixed here.

  1. Single mode loses the current file when the new one is rejected. With multiple="false", _add empties the list before checking the new file. Dropping a file of the wrong type, or one that's too big, removes the file that was there and fires files-change with it as removed. Checking first and replacing only when the new file passes would keep it.
  2. Focus can get lost. _restoreFocus falls back to this._dropEl.focus() when the last file is removed, but .drop has no tabindex, so the call does nothing and focus drops to the page. Focusing the browse button instead would match the header comment's intent.
  3. Dropping on a disabled field opens the file. When disabled, dragenter/dragover return without preventDefault(), so the browser handles the drop itself and navigates to the dropped file, leaving the page. Calling preventDefault() and setting dropEffect = 'none' would block it.
  4. Thumbnail tint is mixed with white. .thumb uses color-mix(… 10%, #fff), so type icons sit on a light square in the amoled theme. Mixing with var(--_bg) would follow the theme.
  5. Clear during a removal. If clear() runs within the 180 ms a row is animating out, that file is listed as removed in two files-change events. Rare, but listeners that count removals would be off by one.
