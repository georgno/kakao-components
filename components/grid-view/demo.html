Grid view

<kakao-grid-view> - a data grid in the manner of Yii2’s GridView: a kakao-table with a filter row under its headings, an action column, a summary and a kakao-pagination. It filters, sorts and pages in the browser, or leaves all three to the server and sends the filters as GET parameters; it also decorates a server-rendered table where it is. On a phone each row wraps into a block of label / value pairs, the filters open from a “Filters” button and the actions sit at the bottom of each block. Light DOM: load table.css, grid-view.css, table.js and grid-view.js; pagination, text input, select and button are used where they are loaded.

Filters, actions and paging

A column with filter gets a field under its heading: true for a search field, a list of options for a dropdown (with “All” first). Searches ignore case and accents and filter after a short pause in typing (filter-delay); every change fires a cancelable filter-change. A column with actions draws icon buttons per row; each is named for its row (“Delete Ada Lovelace”), delete asks first, and row-action says which was used. page-size pages the filtered, sorted rows; the summary above counts them.

Links, selection and page sizes

An action with a url template is a real link ({id} and any {key} of the row filled in, URL-encoded); action-url gives every action a default, as Yii’s ActionColumn does. tone: "danger" uses the danger colour, visible names a row key that must be true. With selectable the selection is kept across pages and filters; selected returns every id. Sorting goes over all rows, by the table’s column types (KakaoTable.types).

Loaded by the page

With mode="server" the grid neither filters nor sorts nor pages. Here the page cancels filter-change and loads the rows itself, as it does on sort-change and page-change, with loading in between; total-items and page drive the summary and the pager. Search fields apply on Enter or when they lose focus.

Script-driven · mode="server"

Server-rendered (Yii2)

Without rows of its own the grid decorates the kakao-table written inside it, as Yii2’s GridView renders it: sorter links in the headings, a filter row (tr.filters) with the server’s own fields, and an action column marked data-type="actions" whose links keep their data-confirm / data-method. A filter change goes to filter-url (default: this address) as GET parameters by the fields’ names, without page. In this demo both events are cancelled and logged instead.

Other words

KakaoGridView.texts sets the words for every grid: summary (“Showing {from}–{to} of {total}”), filtered, none, filters, filterLabel, all, clearFilters, noMatches, noMatchesMessage, actionLabel (“{action} {row}”), view, update, delete and confirmDelete. The table’s and the pager’s words are their own.
