## ADDED Requirements

### Requirement: One stylesheet
`shared/kakao.css` SHALL hold `shared/tokens.css`, `shared/font.css` and `shared/themes.css`, in that order, unchanged, so a page can load tokens, font and themes with one link. It SHALL be generated by `node tools/loader.js` and never edited by hand.

#### Scenario: A token changes
- **WHEN** a value in shared/tokens.css changes and kakao.css is not regenerated
- **THEN** `node tools/loader.js --check` exits with code 1 and names kakao.css

### Requirement: Loader
`shared/kakao.js`, loaded in the head without `defer`, SHALL apply a saved theme before the first paint, and load every kakao component the page uses on first use: shared/component-api.js before any component, then for each component the components it requires and those it is enhanced by, its light-DOM CSS (inserted where the loader script is, so page CSS after it still wins), then its script, each script after the scripts it depends on. It SHALL find tags in the parsed page and in markup added later, and a `theme-picker` control SHALL load the theme switch. It SHALL load files relative to its own URL, keeping that URL's query, and SHALL skip tags that are already defined and files the page already loads. Until a tag is defined it SHALL be hidden (visibility); it SHALL be shown when its file or a file it requires fails to load (also a script the page loads itself), and at the latest 3 s after it was found, while other tags stay hidden until ready. A saved theme SHALL set data-kakao-theme and data-bs-theme before the first paint, as theme-switch.js does. `kakaoLoader.load(...tags)` SHALL load tags on demand and resolve once they are defined; `kakaoLoader.ready` SHALL resolve once everything the parsed page uses is loaded.

#### Scenario: Toast through the loader
- **WHEN** a page loads only kakao.css and kakao.js and contains `<kakao-toast>`
- **THEN** stack.js and alert.js run before toast.js and the toast works

#### Scenario: A required file fails
- **WHEN** the page's own stack.js returns 404 and the page contains `<kakao-toast>` and slow-loading `<kakao-tabs>`
- **THEN** the toast is shown at once, the tabs stay hidden until defined, and `kakaoLoader.ready` resolves

#### Scenario: Tabs added later
- **WHEN** a script adds `<kakao-tabs>` after the page has loaded
- **THEN** tabs.css and tabs.js are loaded and the tabs are styled

### Requirement: Generated map
The loader's dependency map (per tag: script, light-DOM CSS, requires, enhanced by) SHALL be generated by `node tools/loader.js` from custom-elements.json, between generated markers in shared/kakao.js. `--check` SHALL exit with code 1 when the map or kakao.css differs from its sources; the pre-commit hook and the deploy SHALL run it.

#### Scenario: New dependency
- **WHEN** a component header adds a `requires` entry and the manifest is regenerated
- **THEN** `node tools/loader.js --check` fails until the loader is regenerated
